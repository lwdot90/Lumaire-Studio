## Numerical definitions

The [existing pixel contract](pixel-semantics.md) remains in force. Normal uses
linear premultiplied source-over. Artistic overlap uses bounded encoded sRGB;
non-overlap retains original extended linear RGB. For source/backdrop alpha
`aS`, `aD`, linear premultiplied channels `s`, `d`, and encoded overlap function
`B(D,S)`, the output is:

```
s * (1-aD) + aS*aD*decodeSrgb(B(D,S)) + d*(1-aS)
aS + aD*(1-aS)
```

`D` and `S` below are bounded encoded overlap components. Original Color Burn
and Color Dodge precedence is retained: Burn returns 1 for `D=1` before testing
`S=0`; Dodge returns 0 for `D=0` before testing `S=1`.

| Appended mode | B(D,S) |
|---|---|
| Linear Burn | max(0,D+S-1) |
| Linear Dodge | min(1,D+S) |
| Soft Light | D-(1-2S)D(1-D) when S<=0.5; otherwise D+(2S-1)(g(D)-D) |
| Hard Light | 2DS when S<=0.5; otherwise 1-2(1-D)(1-S) |
| Vivid Light | Burn(D,2S) when S<=0.5; otherwise Dodge(D,2S-1) |
| Linear Light | clamp(D+2S-1,0,1) |
| Pin Light | min(D,2S) when S<=0.5; otherwise max(D,2S-1) |
| Hard Mix | Frozen nearest 12-bit encoded-code sum >=4096, with raw Burn/Dodge corner precedence; see below |
| Exclusion | D+S-2DS |
| Subtract | max(0,D-S) |
| Divide | 1 when S=0; otherwise min(1,D/S) |

For Soft Light, `g(D)=((16D-12)D+4)D` when `D<=0.25`, otherwise `sqrt(D)`.
Soft Light, Hard Light and Exclusion follow the frozen
[W3C 21 March 2024 blending definitions](https://www.w3.org/TR/2024/CRD-compositing-1-20240321/#blending).
The remaining extensions are explicit Linux definitions, including singular
endpoints. Divide defines black over black as white; Vivid Light and Hard Mix
inherit Burn/Dodge corner precedence, so white over black remains black and
black over white remains white. These cases are pinned by scalar tests.

Hard Mix is discontinuous: tiny CPU/GPU `pow` differences around an encoded
half threshold can flip the result between black and white. Its interior
classification therefore uses a frozen nearest 12-bit encoded grid, exclusively
for this newly added mode. For each `q=0..4095`, the threshold is the exact FP32
bit pattern of `decodeSrgb((q+0.5)/4096)`. Binary search compares the original
premultiplied channel against `threshold*alpha` in FP32; equality selects the
upper code. It never divides by alpha or invokes a transcendental during
classification. A sum of source/backdrop codes >=4096 selects white, otherwise
black. Before quantization, backdrop >=alpha selects white, backdrop <=0 selects
black, source <=0 selects black, and source >=alpha selects white, in that order.
This retains Burn/Dodge corner precedence, including extended overlap clipping.
The encoded nearest-code resolution is 1/4096 and introduces an explicit
half-step classification band; no existing 13-mode behavior is changed.

The shared [CPU threshold header](../core/hard_mix_thresholds.h) is generated by
[generate_hard_mix_thresholds.py](../tools/generate_hard_mix_thresholds.py).
Run `python3 tools/generate_hard_mix_thresholds.py --check` to verify their
exact bits, CPU/GPU fixture pairs and readonly SSBO upload/fetch wiring, or
`--write` to regenerate the shared header. The frozen little-endian
FP32 threshold-byte SHA-256 is
`d8d31dbb7e76c9dd37563895b4f6edcae7cc69512c83aafa936bffaf9dd40514`.
The scalar table has static storage. Each blend kernel uploads that same 16 KiB
bit array into one admitted, readonly Vulkan storage buffer at binding 3,
retained until kernel destruction. Shader invocation lookup reads that shared
buffer, avoiding a writable table per invocation. A 4096-case shader switch was
removed because driver compilation exceeded the low-resource working envelope;
this buffer preserves the numerical classification without that compilation
cost. Eight independently specified
threshold/complement pairs pin black below, white at equality and white above
using adjacent FP32 samples, with exact soft-alpha analytical outputs. GPU tests
assert the same outputs without a Hard Mix tolerance exception.

This contract supplies the legacy upstream mode names and deterministic Linux
behavior. It does not establish Photoshop or macOS Core Image pixel equality;
those require separately recorded application fixtures and compatibility
policies. No Fill-sensitive rules, Dissolve, Darker Color, Lighter Color or
isolated-group semantics are added here. Existing saved identifiers retain their meanings. Native schema 2 enables
these appended modes and inherited folder opacity; the schema-1 reader
preserves its original appearance restrictions. Broader compatibility policies
still require a separately specified versioned extension.

## Verification

`blend_test` covers all 24 identifier round trips, a 9-color cross-product at
four source/backdrop alpha values, bounded and transparent endpoints, independent
analytic values for all appended modes, both Soft Light curve branches, all
black/white extension corners, soft-source and soft-backdrop non-overlap, the
Hard Mix half threshold, and extended RGB without overlap. Existing analytical
nonseparable and Burn/Dodge regressions remain. Compilation and execution belong
to the coordinating parent, to keep compiler jobs serial on the low-resource
machine.
