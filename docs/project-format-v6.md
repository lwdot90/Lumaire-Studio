# Linux project format version 6

Version 6 retains the exact version 5 SQLite table layout, application ID, canonical RGBA16F tile encodings, checksums, source ICC handling and 100 MP aggregate source/mask limits. `PRAGMA user_version` is 6. The writer publishes a replacement only after validated preflight and the existing transactional, synchronized save protocol. Readers continue to accept versions 1–5 under their original envelope rules.

Document `selection_json` is `null` or canonical compact JSON version 2. It has `shape` (`rectangle`/`ellipse`), `bounds` (four canonical decimal integer strings), `inverted` (boolean), and `featherRadius` (finite document-pixel number, 0–256). Version 1 selections in older projects imply zero feather. Unknown fields and noncanonical representations are refused.

Plain raster/folder records remain version 1. Adjustment-only records remain version 3 (as in file version 5); version 2 adjustment records are accepted only in version 4 files.

A retained retouch raster uses canonical layer record version 4 with `kind:raster`, `policy:1`, `source`, `intermediate`, `intermediateRevision`, `rendered`, `revision`, `sampling`, `strokes`, and `adjustment`. UUIDs identify the immutable original source, retouch result and final adjustment result; revisions are canonical unsigned decimal strings no greater than INT64_MAX. The stored asset points to the original source. Derived results are replayed, not persisted as additional tile payloads. Duplicated placements retain shared intermediate/final cache identities; conflicting identities are rejected. With no adjustments, intermediate and rendered identities and revisions must match.

`adjustment` is an empty string or the canonical version 3 adjustment record encoded as a JSON string. Its source identifies the intermediate result; its rendered identity, revision and sampling must match the outer record. Replay runs retained retouch strokes in order and then the adjustment stack.

Each stroke is an eleven-element array: kind (0 Clone, 1 Heal), source anchor `[x,y]`, ordered destination points `[[x,y],…]`, diameter, hardness, opacity, healing radius, local-to-document affine `[a,b,c,d,tx,ty]`, frozen selection or null, canvas width, canvas height. A frozen selection is `[x,y,width,height,shape,inverted,featherRadius]`, with the first four entries canonical decimal integer strings and shape 0 Rectangle/1 Ellipse. Stroke validation follows `core/retouch.h` and its policy 1 implementation. Frozen source offsets, placement, selection and strength are retained exactly. Diameter and healing radius use the captured document-pixel coordinate frame; replay maps that frame through the saved affine rather than changing earlier stroke settings.

At most 16 strokes and 32768 total points are accepted. A complete retouch envelope is capped at 2 MiB; each stroke has at most 8192 points. This admits the engine’s 32768 total-point bound without the previous 64 KiB adjustment-only envelope restriction. Adjustment-only records retain their 64 KiB cap. Every layer parameter record contributes to the shared 4 MiB document metadata bound. Refusal occurs before creating a replacement file and preserves the previous project. Parsing, graph validation, asset identity validation and metadata bounds precede tile decoding; conflicting derived cache identities are checked before their replay. Cancellation is checked before publication and during tile IO and retouch/adjustment evaluation.

When loading through an admitted TileStore, retained retouch metadata is charged for the stack, stroke-vector capacity, point-vector capacities and shared ownership overhead. The charge follows the immutable stack through document/history sharing and is released with its last owner. Duplicate placements share the stack and charge. Parser scratch remains a separate worker reservation.
